# Комплексная банковская выписка

Python CLI собирает сведения о действующих счетах и вкладах, заказывает исходные банковские PDF и сохраняет комплексную выписку в JSON с отдельным отчётом о полноте. Первый реальный адаптер — ВТБ Онлайн; воспроизводимая демонстрация работает через локальный синтетический кабинет в Chromium.

## Установка

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/) и Chromium для Playwright:

```sh
uv sync --frozen
uv run playwright install chromium
```

На Linux для браузера могут потребоваться системные зависимости: `uv run playwright install --with-deps chromium`. Для синтетических PDF нужен шрифт с кириллицей: используются DejaVu Sans на Linux или Times New Roman на macOS. Другой TrueType-шрифт можно указать переменной `SYNTHETIC_FONT=/path/to/font.ttf`.

## Синтетическая демонстрация

```sh
uv run python src/main.py --source synthetic \
  --from 2026-10-01 --to 2026-10-08 \
  --automated --output runs/demo --document-wait-seconds 5
```

`--automated` разрешён только для придуманных данных: выполняет синтетический вход и согласие, запускает headless Chromium. Без этого флага открывается отдельное окно: нажмите «Войти» в синтетическом кабинете, затем подтвердите вход и чтение в терминале.

Ожидаемый результат: `full` (полная выписка), три продукта (счёт карты, накопительный счёт и срочный вклад), одна подтверждённо связанная карта, три операции по счетам. Счёт карты содержит две отдельные расходные записи по `-10.00 RUB`, вклад — поступление `5.00 RUB`; история карты не добавляется к этим операциям. Доступный остаток карты `75.50 RUB` хранится отдельно. PDF счёта карты многостраничный, с многострочным описанием и продолжением на другой странице; PDF накопительного счёта содержит явную пустую историю и пустую вторую страницу. Вклад открыт 5 октября, поэтому его период извлечения — 5–8 октября.

Новая папка нужна для каждого самостоятельного запуска. Коды завершения: `0` — полная выписка; `2` — частичная выписка, ошибка запуска или входных параметров; `3` — отказ от чтения. `--consent no` прекращает запуск до открытия браузера.

Для демонстрации частичного результата задайте `--scenario download-failure`, `card-failure`, `malformed`, `expiry`, `pending` или `uncertain`, каждый раз с новой папкой. `identity-mismatch` меняет свежие реквизиты счёта, сохраняя прежнюю идентичность PDF, и демонстрирует отказ от неподтверждённого документа.

## Реальный запуск на личном кабинете ВТБ

Есть несколько вариантов реального запуска:

### 1. Chromium с установленными сертификатами

ВТБ Онлайн использует российские TLS-сертификаты. Chromium из Playwright может не доверять их центру сертификации: окно открывается и закрывается до ручного входа, а CLI сообщает `ERR_CERT_AUTHORITY_INVALID`. Установите сертификаты по [официальной инструкции ВТБ](https://www.vtb.ru/crt/) и повторите запуск. По умолчанию проверка HTTPS включена.

```sh
uv run python src/main.py --source vtb \
  --from 2026-10-01 --to 2026-10-08 \
  --output runs/vtb-demo --document-wait-seconds 60
```

### 2. Альтернативный поддерживаемый браузер

Другой вариант — установить Яндекс Браузер, который [рекомендует ВТБ](https://www.vtb.ru/crt/), и явно выбрать его исполняемый файл. Для стандартной установки на macOS:

```sh
uv run python src/main.py --source vtb \
  --from 2026-10-01 --to 2026-10-08 \
  --output runs/vtb-demo --document-wait-seconds 60 \
  --browser-executable /Applications/Yandex.app/Contents/MacOS/Yandex
```

Укажите фактический путь, если браузер установлен в другом месте. CLI создаёт отдельный временный профиль и не использует вашу существующую авторизацию. Совместимость установленного браузера с Playwright и вход в реальный кабинет требуют проверки на вашей машине; Яндекс Браузер пока не проверен в этом проекте.

### 3. Пропуск проверки сертификата

Ещё одна альтернатива — явно включить `--ignore-https-errors`, который передаёт `ignore_https_errors=True` в браузерный контекст Playwright:

```sh
uv run python src/main.py --source vtb \
  --from 2026-10-01 --to 2026-10-08 \
  --output runs/vtb-demo --document-wait-seconds 60 \
  --ignore-https-errors
```

> **Это - небезопасная опция: используйте на свой страх и риск.** Она отключает проверку TLS-сертификатов для всех запросов в браузерном контексте этого запуска, включая переходы и загрузки, что допускает подмену сайта и перехват банковских данных. CLI выводит предупреждение до открытия браузера. Флаг можно сочетать с `--browser-executable`; настройка не сохраняется между запусками и не заменяет ручной вход и согласие на чтение.

### Дальнейшие действия

В открывшемся окне войдите самостоятельно и закройте рекламные окна. Нажмите Enter в терминале, затем явно разрешите чтение словом `да`. До этого адаптер не обнаруживает продукты и не заказывает документы. 


## Продолжение работы после прерывания

```sh
uv run python src/main.py --source synthetic \
  --from 2026-10-01 --to 2026-10-08 \
  --automated --output runs/demo --resume
```

Для ВТБ также используйте исходную папку, период и `--resume`, затем снова войдите вручную и разрешите чтение. 

```sh
uv run python src/main.py --source vtb \
  --from 2026-10-01 --to 2026-10-08 \
  --output runs/vtb-demo --resume --document-wait-seconds 60
```

Контрольная точка сверяется со свежим source reference, полным номером счёта, периодом, версией схемы и SHA-256 файла; содержимое PDF дополнительно проверяется парсером. Для карты заново подтверждаются связь и уникальные последние четыре цифры. При несовпадении контрольной точки или изменении файла документ скачивается заново. Сохранённые результаты служат контрольными точками. Текущая реализация заново разбирает PDF, чтобы перепроверить идентичность и нормализацию. Исходное время получения сохраняется: продолжение объединяет части разных моментов и не обещает единого свежего снимка.

> **Известный дефект:** PDF попадает в контрольную точку до проверки его содержимого. Если банк изначально выдал повреждённый документ, другой номер счёта или период, парсер отвергает его и не включает его данные в итог, но `--resume` снова берёт тот же файл с совпадающим SHA-256. Автоматической замены отвергнутого документа нет; результат остаётся `partial`. Обход — новый самостоятельный запуск с новой папкой результата. Это отличается от повреждения файла после сохранения: такое изменение обнаруживается по SHA-256.

## Результат и проверка полноты

Папка запуска содержит:

- `statement.json` — общий период, продукты со сведениями и счётной сводкой, отдельные карты, операции, документы с происхождением и отчёт;
- `report.json` — статус, охват, количества, этапы/причины ошибок и покрытие полей;
- `documents/*.pdf` — исходные документы;
- `progress.json` и `result-*.json` / `card-result-*.json` — локальные контрольные точки.

Схема версии 1: деньги — `{ "amount": "-10.00", "currency": "RUB" }`, даты — ISO, источник поля — `{ "value": ..., "status": "known|absent|failed", "reason": ... }`. `absent` описывает отсутствие значения/подтверждённой семантики в изученном источнике; `failed` означает ошибку чтения. Отсутствующие категории и статусы операций не придумываются. Обе даты банковской строки сохраняются без выдуманного времени; определяющая дата фильтра пока не подтверждена, поэтому основание периода явно обозначено как период документа банка.

`full` требует подтверждённого окончания обнаружения, применимых счётных и карточных документов, совпадения идентичности/периода, обработки всех страниц и отсутствия отклонённых строк/ошибок чтения. Покрытие отсутствующих полей и `not_applicable` отражаются отдельно. Ошибочная строка исключается из нормализованных операций, её происхождение сохраняется в частном результате, а число и безопасная причина — в отчёте. Технический повтор определяется идентичностью документа/страницы/таблицы/строки; одинаковые даты, суммы и описания не удаляют реальные записи. Связь с другим собственным продуктом устанавливается только по явно присутствующему полному номеру счёта и единственному сопоставлению.

В [примере `statement.json`](examples/statement.synthetic.json) находятся исключительно придуманные данные успешного синтетического запуска: три продукта, одна карта, три операции, четыре документа и ноль отклонённых строк. Пути PDF заменены на относительные `runs/demo/documents/...`; сами PDF создаются командой демонстрации. Время чтения и идентификаторы документов меняются между запусками.

| Раздел схемы версии 1 | Содержание |
| --- | --- |
| `requested_period` | Включительные границы `start` / `end`. |
| `products[]` | `product` со сведениями и реквизитами; статус обработки, период извлечения, счётная сводка `statement`. |
| `cards[]` | `card` с маской, подтверждённой связью и отдельным доступным остатком; статус обработки. Название и валюта карты отдельными полями не представлены; валюта показателя находится внутри суммы. |
| `operations[]` | `product_id`, `document_id`, обе даты `occurred_at` / `processed_at`, сумма, описание, дополнительные поля и `provenance` с исходными ячейками. Идентификатор операции банка отдельным полем не представлен: в поддержанном формате он не извлекается. |
| `documents[]` | Идентичность документа и продукта/карты, период, `acquired_at`, путь PDF. |
| `report` | Статус, охват, счётчики, причины ошибок, покрытие полей и ограничения снимка. Тот же объект сохраняется в `report.json`. |

Схема не содержит верхнеуровневых `bank`, `client` и единого `extracted_at`; время относится к чтению баланса и получению отдельных документов. Формальная JSON Schema пока не опубликована. Для интерпретации отдельного `report.json` до исправления его схемы нужно читать `requested_period` из соседнего `statement.json`.

Выходные файлы содержат частные банковские данные. `runs/` исключена из Git; CLI отказывает в записи внутри репозитория, если выбранная папка не исключена. Новые папки создаются с правами `0700`, JSON — `0600`, CLI ограничивает права создаваемых файлов через umask. Консольные сообщения и отчёт об ошибках не включают номера счетов, исходные страницы, сессионные токены или сырой текст банковских ошибок. Исходные личные PDF/HTML/DOCX также исключены из Git.

Номера банковских счетов сохраняются для проверки идентичности и связывания продуктов; это не номера карт. Исходные PDF, описания операций, исходные ячейки и отклонённые строки сохраняются без фильтрации содержимого. Если в них появится полный номер карты или иной секрет, он также попадёт в локальные артефакты. На синтетическом PDF с тестовым номером карты подтверждено его попадание в JSON; утечка реальных данных этим не утверждается. Прототип не реализует шифрование хранилища, срок удаления данных или очистку секретов внутри банковского PDF. Права файлов и исключение из Git не заменяют этих мер; существующая папка результата автоматически не получает новые права.


## Проверки и тесты

```sh
uv run pyright
uv run pytest
```

Тесты запускают локальный HTTP-сервер и Chromium; среда должна разрешать loopback и запуск браузера. Проверяются полноценный CLI, многостраничность, пустая страница, пустая история, переносы описаний, ошибки загрузки/карты, повреждённые строки, незавершённое формирование, истечение сессии, продолжение после нового входа и несовпадение идентичности.

## Допущения и технический долг

Принятые допущения: 
- Русский интерфейс и текущая разметка ВТБ; 
- Отдельные времена получения вместо атомарного снимка. 
- Только рублёвые продукты в браузерном адаптере. Нормализатор денег допускает отдельную валюту, но это не означает поддержку валютных продуктов реальным адаптером. 
- Универсальные справочники категорий/статусов и восстановление точного состояния браузера не реализованы. Отсутствие значения или подтверждённой семантики в изученном источнике не доказывает его отсутствие во всех каналах банка.
- PDF с текстовым слоем и поддержанной геометрией таблиц, OCR не реализован.

Приоритетные незакрытые дефекты:

1. **Приватность:** обеспечить запрет хранения полных номеров карт и других секретов во всех артефактах, включая исходные PDF и ячейки, с проверками на синтетических примерах. Маска идентичности карты не защищает произвольный текст операции.
2. **Восстановление после падения и повреждений файлов:** различать полученный и проверенный PDF; исключать отвергнутый документ из повторного использования и позволять получить исправный. Сейчас неверный исходный PDF закрепляется в контрольной точке.
3. **Наблюдаемость:** добавить запрошенный период в самостоятельный отчёт и безопасный журнал этапов. Текущие итоговые причины ошибок не являются хронологическим техническим логом.

Дальнейший долг поддержки: 
- Установить реальный маршрут срочного вклада и критерий окончания списка продуктов; расширить фикстуры при изменениях DOM/PDF. 
- Парсер привязан к заголовкам и геометрии ВТБ, а конвейер вызывает его напрямую: для нового банка недостаточно реализовать только `SourceAdapter`, нужен выбор или расширение парсера.
- В целом требуется анализ кабинетов других банков для понимания, какие поля и операции можно обобщить, а какие вынести в отдельные адаптеры банков. После чего потребуется глубокий рефакторинг.
- Экспорт и контрольные точки собираются вложенными словарями; формальной валидации общей схемы и миграций нет. 
- Подключение CSV/XLS, кредитов и закрытых продуктов.


## Соответствие заданию и границы прототипа

Прототип в основном реализует согласованный сокращённый объём. Полное соответствие исходной постановке не заявляется.

| Требование исходного задания | Реализация и границы |
| --- | --- |
| Управляемый браузер, самостоятельный вход, явное согласие | Реализовано. Отдельный временный контекст Playwright; автоматический вход и согласие разрешены только для синтетических данных. Подключение к существующему профилю не реализовано. |
| Обнаружение продуктов и их сведений | Основной и накопительный счета, связанные дебетовые карты; срочный вклад в синтетическом кабинете. Кредиты, кредитные карты и закрытые продукты пока не поддерживаются. Реальный маршрут срочного вклада не установлен; полного охвата ВТБ нет. |
| История за период, все страницы, динамическая загрузка | Автоматический заказ банковского PDF, ограниченное ожидание, разбор всех страниц и переносов строк. Пагинация истории покрывается страницами PDF, а не перебором экранной таблицы. CSV/XLS и произвольные формы экспорта пока не поддерживаются. |
| Нормализация и связь с продуктами | Обе даты, точные суммы, валюта, описание, доступный контрагент, происхождение строки; недоступные поля имеют причину. Тип, категория и статус не выводятся из описания. Связь для подтверждения внутреннего перевода требует явного полного номера другого счёта. |
| Воспроизводимый результат и пример | JSON, lock-файл, генерируемые HTML/PDF-фикстуры, синтетический CLI и [полный пример результата](examples/statement.synthetic.json). Схема отличается от иллюстративной схемы задания. |
| Частичные ошибки и полнота | Доступные корректные данные сохраняются, пропуски дают `partial`. Адаптер ВТБ всегда имеет неподтверждённое окончание списка продуктов. В восстановлении отвергнутого PDF остаётся дефект. |
| Технический лог и отчёт с периодом | Реализованы итоговые отчёты и безопасные причины ошибок. Отдельного журнала этапов нет; запрошенный период есть в `statement.json`, но отсутствует в самостоятельном `report.json`. |
| Приватность и отсутствие хранения секретов | Ручной вход, отсутствие сохранённой авторизации, минимальный набор реквизитов, ограниченные права файлов, безопасная диагностика. Автоматическое маскирование полных номеров карт в содержимом PDF/операций не реализовано: абсолютная гарантия отсутствия таких номеров в артефактах не обеспечена. |
| Модульность и проверки ключевых сценариев | Браузерный источник, модели, нормализация, разбор, конвейер и хранилище разделены; тесты покрывают несколько продуктов, страницы, пустую историю, загрузку, варианты дат/сумм и продолжение. Для другого банка с иным PDF понадобится также адаптация парсера. |


### Детали работы и реализации

`adapters.py` задаёт границу источника. `browser_source.py` содержит селекторы ВТБ и отдельно синтетический контракт полноты/вклада. `synthetic.py` генерирует локальный кабинет и придуманные PDF. `parsing.py` читает все страницы, текст и таблицы через [pdfplumber](https://github.com/jsvine/pdfplumber); текстовый слой и геометрия подходят для предоставленных образцов, OCR не реализован. `operations.py` нормализует строки и связывает продукты. `pipeline.py` сохраняет доступные результаты и оценивает полноту. `storage.py` атомарно пишет файлы и проверяет контрольные точки. Загрузки сохраняются до закрытия браузерного контекста.

Авторизация, cookies и браузерный профиль между запусками не сохраняются. Незнакомый диалог или изменённые элементы интерфейса отражаются как ошибка этапа, а имеющиеся результаты сохраняются.

Адаптер использует вручную обнаруженные маршруты MasterAccount, SavingsAccount и DebitCard / MasterAccountCard. Связь карты со счётом устанавливается единственным совпадением полных номеров в свежих реквизитах; маски и одинаковые остатки этого не доказывают. Для каждого счёта берётся пересечение запрошенного периода с подтверждённой датой открытия. Если пересечения нет, статус `not_applicable`, PDF не заказывается.

Последние четыре цифры карты читаются из маски в видимом тексте или из подписанного `aria-label` элемента карты: ВТБ сообщает их после слов «с последними цифрами», в том числе двумя парами цифр. Если рядом отображены четыре цифры без звёздочек, они сверяются с этой подписью. Противоречащие значения дают `ambiguous_card_mask_in_source`; произвольные числа и суммы не используются как номер карты. Уникальность последних цифр среди найденных карт и соответствие карточному PDF проверяются отдельно.

Для отложенной выписки основного счёта заказ отправляется один раз, затем проверяется «Мои выписки» и ограниченно нажимается «Обновить». Выбирается единственная готовая строка с точным периодом текущего продукта; несколько подходящих строк дают ошибку неоднозначности. PDF проверяется по полному номеру счёта и периоду. Незавершённое формирование даёт `partial`; сведения об отправленном заказе сохраняются, чтобы `--resume` проверял историю без повторного заказа.

**Границы проверки:** ручные наблюдения подтверждают маршруты, реквизиты и сохранение PDF счёта карты, накопительного счёта и самой карты. Парсер проверен на трёх предоставленных PDF. Автоматический адаптер проверен на синтетическом браузерном сценарии; полный автоматический запуск в реальном кабинете ещё не выполнен. Автоматическое получение из сетевого PDF-ответа/новой blob-вкладки также требует живой проверки. Срочный вклад покрыт только синтетически; реальный маршрут вклада не установлен.

На наблюдённой странице ВТБ нет подтверждённого признака окончания списка продуктов. Реальный адаптер сохраняет найденные продукты и возвращает `partial` с причиной `vtb_inventory_end_not_confirmed`. Закрытые продукты исключены из первой версии. Гарантия полного охвата всех клиентов ВТБ не заявляется.

Заголовки разделов могут появиться раньше продуктов. Адаптер ждёт хотя бы одного видимого заголовка каждого известного раздела; скрытые и повторяющиеся заголовки не считаются неоднозначностью идентичности продукта. Перед чтением списка и после каждого возвращения в него адаптер ждёт появления известных элементов продуктов и неизменного состава в течение 500 мс. Сравниваются семейства элементов, их порядок, исходные идентификаторы и подписи. Изменившийся список даёт `inventory_changed_during_read`; отсутствие стабильного списка — `inventory_not_stable_within_budget`. Это ограниченная проверка готовности, а не подтверждение полноты: продукты, появившиеся после окна стабилизации, всё ещё могут быть пропущены. Рекламное окно, появившееся во время ожидания, даёт `unexpected_modal`.

При ошибках отдельных продуктов `report.json` сохраняет дополнительные причины с `family`, индексом элемента `index` (с нуля), этапом `stage` и безопасной причиной `reason`. Например, `MASTER_ACCOUNT` / `product_details` / `page_element_timeout` означает, что нужный элемент страницы основного счёта не появился вовремя. `page_navigation_timeout` относится к переходу на страницу, `inventory_sections_timeout` — к ожиданию разделов списка. Тексты браузерных исключений, подписи продуктов и личные реквизиты в эти причины не записываются.

При медленном интернете увеличьте `--page-wait-seconds`, например до `120`. По умолчанию каждое ожидание перехода или элемента, а также стабилизация списка ограничены 60 секундами; допустимый диапазон — больше 0 и до 300 секунд. `--document-wait-seconds` отдельно задаёт бюджет получения PDF. Адаптер не использует кнопку «назад»: он открывает известные маршруты, не перезагружая страницу, если уже находится на нужном маршруте. После клика по продукту повторной загрузки его страницы нет, а первый продукт читается из уже подготовленного списка. Если при переходе кратковременно появляется `/login`, адаптер ждёт целевой маршрут; если кабинет не восстановился в отведённое время, сохраняется `session_expired` и чтение прекращается.

Разовый сетевой обрыв, прерывание навигации или смена контекста страницы во время чтения списка продуктов допускают ещё две попытки с короткой паузой. На повторе список загружается заново, даже если адрес остался прежним после ошибки. Каждая попытка использует настроенные бюджеты ожидания. Постоянный сбой даёт безопасную причину, например `network_connection_reset` или `page_context_changed`; неизвестная ошибка браузера — `inventory_browser_action_failed`. Истечение сессии, неизвестные модальные окна и отправка заказа PDF этим механизмом не повторяются.

Причины ошибок обнаружения также содержат `browser_operation` и `browser_error`, если доступно исключение Playwright. Например, `Page.goto` / `navigation_interrupted` указывает на прерванный переход, `Page.evaluate` / `javascript_type_error` — на ошибку JavaScript при чтении страницы. Значения выбираются из фиксированных списков; неизвестный код обозначается `unclassified`. Адреса страниц, тексты исключений и журнал вызовов не сохраняются. Диагностика сохраняется и для ошибок, обёрнутых в безопасную ошибку адаптера.

У основного счёта текущий `Баланс` читается отдельно от остатков PDF. Для накопительного счёта смысл суммы в шапке не подтверждён, поэтому она не назначается текущим или доступным балансом. Отдельный доступный баланс счёта на изученных страницах не наблюдался. Доступный остаток карты берётся только из карточного PDF; его время актуальности остаётся неизвестным. Неизвестный смысл/отсутствие поля объясняется в покрытии полей.
